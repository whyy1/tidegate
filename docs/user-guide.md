## 1. 界面布局与快捷键

Tidegate 采用双轴 IDE 测控台骨架：

- **左侧导航栏**：可在窄图标栏与完整菜单间折叠切换；运行压测时「实时压测」图标旁显示脉冲状态点；底部提供 `Ctrl+K` 检索入口、一键 **MCP** 接入入口、**账号与令牌**及退出按钮。
- **顶部上下文栏（TopBar）**：统一完成当前**项目切换**、**环境切换**（直接展示当前激活环境的 `BaseURL` 胶囊）以及当前**临时变量**查看。
- **常用快捷键**：
  - `Ctrl+K` / `⌘K`：打开全局命令面板，模糊搜索接口名称/URL、场景、环境或直接跳转页面。
  - 工作台中间分隔条支持鼠标拖拽以及键盘方向键调整左右/上下分屏比例。

## 2. 接口工作台与批量功能回归

在 **工作台** 视图可完成多协议接口定义与单次调试：

1. **多协议调试**：支持 **HTTP/1.1 & HTTP/2**、**WebSocket**、**gRPC**（支持 Server Reflection 自动发现服务与方法并生成示例 JSON，或加载 `.proto` / 预设参数）与 **SSE** 流式调试。
2. **变量体系（由高到低四级覆写）**：
   - 会话临时变量池 -> 场景/单步覆写变量 -> 环境级变量 -> 项目级变量。
   - 在环境或项目编辑框内勾选 **「密」** 后，变量值将通过 AES-256-GCM 加密存入密钥保险箱（Vault），界面回显与项目导出均自动脱敏为占位符。
   - 请求路径、Query、Header 或 Body 中输入 `{{` 将自动弹出四级变量及内置动态函数补全。
3. **前后置脚本与断言 / 提取器**：
   - 支持纯 Go 受限 AST 脚本（`pre_script` / `post_script`），可读写环境变量及检查 `resp.status`、`resp.body`、`resp.header`、`resp.json`、`jsonpath`。
   - 内置 JSONPath / XPath / 正则提取器，提取结果自动写入临时变量池供后续请求复用。
   - 调试结果右侧提供响应头、格式化 Body、Cookie 以及五段耗时分解（DNS / TCP / TLS / TTFB / Total）。
4. **目录批量功能回归**：
   - 点击工具栏 **批量测试** 选择整个项目或指定目录即可按深度优先顺序依次调试全部接口，自动传递提取变量，并可复制等效 CLI 命令接入 CI 流水线。

## 3. 多步场景编排与数据驱动

在 **场景编排** 视图中可直接复用工作台里的接口定义（接口修改后场景自动生效），无须重复录入请求参数：

- **步骤类型与控制流**：支持引用已有接口或内联请求，提供 `group`（事务分组）、`loop`（计数/条件循环）、`if`（条件分支）、`weighted`（加权分流）以及受限纯 Go `script` 步。
- **数据驱动参数化**：上传 **CSV / JSON / JSONL** 数据文件，可在并发运行阶段自动按行轮询或跨分布式 Agent 分片读取。
- **失败韧性策略（`on_error`）**：针对不同接口步骤单独配置出错处理策略——继续迭代（`continue`）、跳过本轮剩余步骤（`abort_iteration`）或终止当前 VU（`abort_vu`）。
- **负载模型（闭环 VUs 与开环 RPS）**：
  - **闭环（VUs）**：固定/多阶段并发用户数，适合探测系统最大吞吐及排队延迟；通常推荐默认高速引擎（`fast`）或 `std`。
  - **开环（Rate / RPS）**：按固定到达率发压（配置阶段目标 RPS 与 `max_vus`），避免协同省略效应（Coordinated Omission）；在突发性高到达率场景推荐在环境或运行选项中选择 `std` 客户端与合理的 `max_dials_per_sec` 平滑建连参数。
- **开压前容量预估**：运行前可基于步数与思考时间快速预估目标并发所需的吞吐、上行/下行带宽与连接数基线。

## 4. 实时压测、瓶颈识别与历史对比

在 **实时压测** 与 **压测记录** 视图观察系统极限性能与双层瓶颈：

- **实时 1Hz 遥测**：监控每秒请求数（RPS）、错误率、P50 / P90 / P95 / P99 / Max 分位延迟、活跃 VUs 与集群入站/出站带宽。
- **运行时在线调压**：在 `steady` 阶段无需重启即可在线调整目标 VUs 或 RPS、执行优雅停止（`graceful_stop`）或立即中止（`abort`）。
- **双层硬件瓶颈告警**：控制器同时聚合发压机 CPU、内存、网卡带宽及临时端口数。当发压机自身接近饱和时，图表上会标注告警区间提示真实服务端拐点。
- **深度观测与导出**：结束后自动生成 **HDR 延迟直方图（12 分桶）**、时间×延迟热力图与单请求错误采样（支持一键回到工作台复现）；支持导出 **HTML 单文件报告**、**CSV**、**JSON**、**JTL** 与 **HAR 1.2**。
- **多轮基线回归对比**：在 **压测记录** 勾选 `2–6` 条历史运行，点击右上角 **对比** 即可叠加分位曲线并按事务/步骤横向对比回归差异。
- **外部监控集成**：管理员可在 **系统治理 -> 指标外推** 拉取 `/api/v1/metrics/prometheus` 指标，或配置 **InfluxDB v1/v2 / Prometheus Pushgateway** 实时异步外推。

## 5. 分布式零信任 mTLS 集群

当单台发压机端口、带宽或 CPU 不足以支撑目标并发时，可扩展多台 `tidegate agent` 组成零信任集群：

1. 在控制器部署并放行集群 gRPC 端口（默认 `7443`，如容器/NAT 部署请配合配置 `TIDEGATE_CLUSTER_PUBLIC_ADDR`）。
2. 打开 Web 控制台左侧 **集群节点**，管理员点击 **签发加入令牌**（可指定有效期和预设标签如 `zone=cn-east,tier=perf`）。页面顶部自动组装完整的接入命令（已包含 `--join` 与 `--ca-fingerprint`）。
3. 在远程发压机上运行该命令：
   ```bash
   ./tidegate agent \
     --join <控制器IP:7443> \
     --token <一次性加入令牌> \
     --cert-dir ./agent-certs \
     --ca-fingerprint <控制器CA_SHA256指纹> \
     --labels zone=cn-east,tier=perf
   ```
4. 节点完成首次 CSR 换签后证书保存在 `--cert-dir` 目录，后续重启不再需要 `--token` 即可凭双向 mTLS 自动重连；不需要某节点时可在控制台在线吊销其证书。
5. 编排压测时可通过 **节点筛选（`node_selector`）** 定向调度特定地域/标签节点，或设置掉线自动重平衡策略（`redistribute` / `abort`）。

## 6. MCP 2.0 智能体安全接入

Tidegate 内置无外部依赖的纯 Go MCP 2.0 服务端，兼容 Cursor、Claude Desktop、Antigravity 等支持 **Streamable HTTP** 或 **CLI Stdio** 的 AI 客户端。

### 快速配置步骤

1. 在左侧栏底部点击 **MCP**，打开「账号与令牌 -> MCP 客户端接入」。
2. 根据客户端角色选择最小权限快捷按钮：
   - **生成只读 MCP 令牌**（推荐排查与分析报告使用）：绑定 `viewer` 角色及 `["mcp", "read"]` Scope，默认 30 天过期。
   - **生成读写 MCP 令牌**（需要 AI 自动生成接口、场景、运行回归或小规模压测时使用）：绑定 `member` 角色及 `["mcp", "read", "write", "debug", "run"]` Scope。
3. 如需进一步将令牌限制在特定项目，可在 **API 访问令牌** 页签手动创建并勾选「限定项目」。
4. 切换 **Streamable HTTP** 或 **CLI Stdio** 视图，点击 **复制 JSON** 粘贴至 AI 客户端的 `mcp_config.json`。

### 安全防线与默认护栏

- **密钥零出域**：Vault 加密变量与认证敏感请求头在返回给 AI 前统一脱敏。
- **权限四重裁剪**：受管理员全局策略（可关闭 MCP 总开关或禁用 AI 发起压测）、用户角色、Token `scopes` 与项目私有 ACL 联合控制。
- **硬护栏**：MCP 发起的单次压测默认上限为 **200 VUs / 300 秒**，管理员可在 **系统治理 -> 安全护栏** 修改上限或启用出站域名/IP 白名单（SSRF 防护）。所有 MCP 工具调用均记录至 **审计日志**。

## 7. 导入导出生态与 CI 门禁

- **两步安全导入**：在工作台点击 **导入**，支持 OpenAPI 3.0/3.1、Swagger 2.0、Postman v2.1、Apifox、JMeter（`.jmx`）、HAR 1.2、cURL 与 `.tidegate` 归档。选择 **智能合并（`merge`）** 时先预览差异 diff，写入时自动保留团队手工添加的断言、提取器、前后置脚本与接口 ID。
- **生态导出**：在项目管理弹窗支持导出 `.tidegate` 完整归档、OpenAPI 3.0（YAML/JSON）、Postman v2.1；在场景页面支持导出独立 **k6 脚本（`.js`）**。
- **CI/CD 质量与性能门禁**：
  ```bash
  # 目录接口功能回归（失败返回退出码 3）
  ./tidegate test --data ./data --folder "订单核心链路" --env "预发环境" --junit junit-report.xml

  # YAML 场景压测与 SLA 阈值校验（违约返回退出码 3）
  ./tidegate run examples/ping.yaml --out summary.json --csv stats.csv --html report.html --jtl result.jtl
  ```
